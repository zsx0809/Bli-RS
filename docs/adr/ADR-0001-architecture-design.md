## 1. 背景与上下文 (Context)

官方 Android 客户端与常规第三方封装客户端在移动设备上面临严重的资源开销与热量失控问题：
- 常驻后台服务与大量遥测上报，持续占用 CPU 算力与总线带宽。
- 音视频解码链路容易发生软解回退与渲染泄露，导致外壳温升超过 42°C。
- 业务层堆叠严重，缺乏极致的内存与并发控制。

本项目目标为打造一个**纯血 Rust 实现的高性能、低发热、轻量级 Bilibili 客户端（BLI-RS）**。

---

## 2. 架构设计决策 (Decisions)

### 2.1 整体分层架构

采用清晰的单向依赖分层架构：

```
+-------------------------------------------------------------------+
|                           UI & 表现层                             |
|       (Slint / Makepad / Winit + Wgpu 声明式原生 UI)              |
+-------------------------------------------------------------------+
                                  |
                                  v
+-------------------------------------------------------------------+
|                        Core 调度与状态层                          |
|         (Tokio Runtime / 响应式状态管理 / 离线缓存策略)             |
+-------------------------------------------------------------------+
       |                                           |
       v                                           v
+-----------------------------+     +-------------------------------+
|      网络与协议引擎         |     |        音视频渲染管道         |
|  - Wbi 加密签名算法         |     |  - NDK AMediaCodec 硬件直解  |
|  - gRPC / Protobuf 解码     |     |  - ANativeWindow 渲染直通     |
|  - Dash 协议流重组与解析    |     |  - AAudio 原生低延迟音频      |
|  - 实时弹幕无锁流处理       |     |  - Wgpu 弹幕批量实例化渲染    |
+-----------------------------+     +-------------------------------+
```

---

### 2.2 模块划分规范

1. **`bli-proto`（协议与加解密引擎）**
   - 提取 PiliPlus `lib/http/` 和 `lib/grpc/` 中的接口定义。
   - 实现 Wbi 密钥混淆排序与 MD5/SHA 签名算法。
   - 实现 B 站 gRPC Protobuf 编解码（账号、动态、推荐流）。
   - 实现实时弹幕数据包解析（zlib / brotli 解包）。

2. **`bli-media`（多媒体硬解与播放管道）**
   - 封装 Android NDK 原生 C 接口：`AMediaCodec`、`AMediaExtractor`。
   - 视频帧直接丢入 `ANativeWindow` 渲染表面，实现零拷贝 GPU 显示。
   - 音频通过 `AAudio` 直通系统混音输出。
   - 无缝支持 Dash 格式的音视频分轨自动对齐与同步时钟。

3. **`bli-ui`（轻量渲染与交互层）**
   - 纯 Rust 渲染栈，杜绝 JVM/ART 虚拟机介入。
   - 弹幕引擎采用多线程环形队列（RingBuffer）与 GPU 顶点批处理渲染。
   - 极简 Material 风格界面设计，保留视频流、搜索、关注与播放核心路径。
